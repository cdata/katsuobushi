## What happened

The `project-orchestration` skill's only pointer to the `sandbox` skill is
descriptive, not imperative: the frontmatter says it "Complements … the
`sandbox` skill (driving VMs)" and the intro says "It leans on the `sandbox`
skill for the actual VM driving"
(`plugins/katsuobushi/skills/project-orchestration/SKILL.md:11,18`). Nothing
instructs the orchestrator to actually *load* it.

The 2026-08 arcanabasis post-mortem shows the failure mode precisely: the
operator loaded `project` and `project-orchestration` because they were
named, read the "leans on" line, and skipped the sandbox skill anyway — and
then attributed their entire error cascade to that one omission (their item
1: "Everything below in this section follows from that"). The knowledge that
would have prevented each subsequent mistake lives only in the sandbox
skill: `console.log` as the stuck-boot diagnostic (`sandbox/SKILL.md:353`,
`:375`), the `--until-report` semantics (`:226-227`), and stop-vs-remove
recovery. An agent that dispatches without that context is flying the VM
blind.

## Suggested fix

- Add an imperative prerequisite at the **top** of the orchestration skill
  body, before the roles section — e.g.: "**Before dispatching or driving
  any sandbox, load the `sandbox` skill.** This skill covers the
  choreography only; launch diagnostics, liveness semantics, and recovery
  live there, and dispatching without them has caused real incidents."
  Mirror the same line in the frontmatter description ("load the `sandbox`
  skill first") so it is visible at selection time.
- Rephrase the line-18 "leans on" sentence to point at the prerequisite
  rather than merely describing the relationship.
- Consider inlining the two or three facts an orchestrator needs even
  mid-incident with the sandbox skill unloaded (where `console.log` lives;
  that `⚠ no progress` is often benign; stop-vs-remove) as one short
  "if you loaded only this skill" callout — defense in depth against the
  exact skip that happened.
- Bump the plugin skill version per the release ritual.

## Acceptance criteria

- [ ] The orchestration skill's first actionable instruction is to load the
      `sandbox` skill; the frontmatter description says so too.
- [ ] The dispatch and reviewer sections do not assume unstated
      sandbox-skill knowledge without naming the prerequisite.
- [ ] Skill version bumped.
