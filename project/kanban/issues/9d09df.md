## What to build

When the orchestrator resumes a paused instance, refresh the base in that
instance's mirror to the current tip. The guest then rebases its own branch onto
that base and continues.

Today a named instance is resumed from the branch tip already in its mirror
(`resolve_seed` → `Seed::Resume`, `rust/katsuobushi-controller/src/sandbox/
start.rs` lines 451-490). The mirror does not change while the instance sleeps,
so a resumed instance keeps working against the tip it launched from and never
sees work that landed in the meantime. With landing moved to `ready`, a review
loop can span several other cards landing, so this gets worse, not better.

Two halves:

- **Host.** On a resume, put the current tip in the instance's mirror under a
  base name, using the delivery plumbing from card `69d1df`. Settle whether the
  base name is fixed or per-launch, and what happens when the tip has not moved
  (do nothing, rather than churn the guest).
- **Guest.** The provision script clones the mirror and checks out
  `sandbox/$instance` (`lib/sandbox/default.nix` lines 1613-1616). On a resume
  it must also fetch the refreshed base and rebase the instance branch onto it.

The guest rewrites only its own branch, in its own mirror. That is ordinary work
on a topic branch. It is **not** the orphaning fault of card `c1a6e1`, because
the orchestrator never rewrites what the mirror holds — but say so in the prose,
so a later reader does not mistake one for the other.

Settle during the work: what happens when the rebase conflicts. A guest that
cannot rebase cleanly must say so rather than continue on a stale base or leave
a half-finished rebase in its working copy.

## Acceptance criteria

- [ ] An instance paused before another card landed can read that landed change
      in its own clone after it resumes
- [ ] The guest's branch is rebased onto the current tip on resume, and the
      guest's own commits survive it
- [ ] A resume where the tip has not moved changes nothing
- [ ] A rebase that conflicts is reported, not silently half-applied
- [ ] The orchestrator never rewrites a commit in the instance's mirror, and
      the prose distinguishes this from the fault in card `c1a6e1`
- [ ] Tests cover the resume path through the host seam

**1. The guest resume path does not select the branch before rebasing
(blocking).** In `lib/sandbox/default.nix`, the resume branch fetches
`refs/heads/base` and rebases, but never runs `git checkout sandbox/<instance>`
first. If `HEAD` has drifted, the rebase silently operates on the wrong branch.

**2. `deliver.rs`'s module doc overclaims (blocking for this card's honesty,
but the defect is in landed code).** It names base refresh as a use case
`deliver` serves, which it cannot: `deliver` writes `refs/heads/delivered/*`,
while base refresh needs `refs/heads/base`. Tracked on `c55c8c` — this branch's
mirror predates `deliver.rs`, so its implementor cannot fix that file.

On the duplication question I asked: the reviewer's answer is that this card does
**not** redundantly reimplement `sandbox deliver` — the namespaces differ, so
`deliver` cannot serve base refresh as written. The overlap is real but is a
documentation defect in `deliver`, not duplicated logic here.
