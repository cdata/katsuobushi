## What happened

`lib.markdown` and `lib.project` disagree about frontmatter, and a project
consuming both will silently lose card titles.

`lib.markdown`'s Prettier formats **every tracked `.md` file** by default —
including the board's own `project/kanban/issues/*.md`. When a frontmatter
scalar is long enough to exceed the print width, Prettier wraps the value onto
an indented continuation line:

```yaml
# before `markdown format`
title: "Hit points in the heart: damage, the Damaged event, and phase-free death"

# after
title:
  "Hit points in the heart: damage, the Damaged event, and phase-free death"
```

That is valid YAML and Prettier considers it canonical — `markdown lint` is
green on it. But `Note::get_scalar` is line-oriented
(`rust/katsuobushi-controller/src/project/note.rs:81-93`): it finds the `title:`
line, sees `rest.trim()` is empty, and returns `None`. The title reads as
absent.

The line-oriented design is deliberate and well-justified (the module header
explains that a serde round-trip would drop unknown keys, Obsidian's included),
so the fix is probably not "vendor a YAML crate" — but the two libraries
currently cannot both be used on one repo without this hazard.

## Impact

- `project status` renders a blank title for the affected cards.
- The Obsidian Kanban card face renders blank (`title` is the first metadata
  key on the face, per `project/layout.rs:156`).
- `project lint` reports **clean** — the board and notes are consistent, so
  nothing surfaces the damage.
- It is silent and retroactive: the cards were filed correctly, and a later
  unrelated `markdown format` run is what breaks them.

Observed in the wild on `cdata/arcanabasis`: three cards with long titles
(`a94bd2`, `f750a2`, `92f888`) went blank after a routine `markdown format`
invoked to satisfy that project's own lint gate.

## Reproduction

1. In a repo wiring both `lib.markdown` and `lib.project`:
   `project new --title "A title long enough to exceed Prettier's print width once the key and quotes are counted"`
2. `markdown format`
3. `project status` → the card's title column is empty.
4. `project lint` → `clean`.

## Expected

Some combination of:

- `get_scalar` understands a wrapped scalar — read the continuation line(s)
  when the key's own line is empty and the next line is more-indented. This
  keeps the line-oriented editor and its byte-for-byte preservation guarantee;
  only the _reader_ grows.
- `lib.markdown` excludes the board directory by default (or `lib.project`
  contributes an ignore entry), so Prettier never rewrites card frontmatter.
- Failing either, `project lint` should flag a card whose `title` parses empty
  rather than reporting clean — silent blanking is the sharpest edge here.

## Acceptance criteria

- [ ] A card whose frontmatter Prettier has wrapped still reports its title

- [ ] `markdown format` followed by `project lint` cannot leave a card with a
      silently empty title
- [ ] A regression test covers a wrapped `title:` scalar in `note.rs`

## Review notes

**Peer review (independent agent), 2026-08-04 — blocking finding, fixed.**

Prettier explodes a flow list one-item-per-line **with a trailing comma** once
it is long enough (~9 short ids / 7 labels at `printWidth = 80`). The regression
fixture pinned only the narrower single-indented-line shape, so the exploded
form — the common one for a real label set — was untested, and the trailing
comma parsed as a phantom empty item that reached `--json`, `project status`,
and the Obsidian card face. `blocked_by` escaped only because `CardId::parse`
filtered it out.

Fixed: `parse_flow_list` drops items whose *raw* text is blank (so an explicit
`""` still round-trips), plus fixtures for the exploded shape on both `labels`
and `blocked_by`. Two further `folded_continuation` misparses found in the same
pass — a blank line inside a quoted scalar yielding a value with a stray opening
quote, and a `#` comment folded into the value — now report absence instead,
which `lint`'s `empty-title` surfaces.
