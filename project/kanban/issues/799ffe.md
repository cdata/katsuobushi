## What to build

Teach the guest to read a heartbeat file. A heartbeat lives in
`.katsuobushi/heartbeats/` in the workspace repo and is YAML:

```yaml
label: Compiling
timeout: 45m
interval: 10s
check: |
  pgrep -f 'rustc|cargo' >/dev/null
detail: |
  echo "$(ls target/debug/deps | wc -l) units"
```

- `label`, `timeout` and `check` are required. `interval` and `detail` are
  optional. An absent `interval` means the transport cadence of 10 seconds.
- `timeout` and `interval` are durations (`45m`, `10s`).
- `check` and `detail` are shell bodies carried in block scalars.

This card is the parser and the type, not the runner. A file that will not read
or will not parse produces a typed error that names the file and the reason —
the runner (a later card) decides what to do with it.

A YAML parser enters `rust/katsuobushi-sandbox-guest`, which carries only
`serde_json` today. Block scalars need real YAML; hand-rolling is harder than
the frontmatter parser in
`rust/katsuobushi-controller/src/project/note.rs`.

## Acceptance criteria

- [ ] A file with `label`, `timeout` and `check` parses into a heartbeat value.
- [ ] A file with no `interval` parses with an interval of 10 seconds.
- [ ] A file with no `detail` parses, and shows its label alone.
- [ ] A file that is missing a required field, or is not valid YAML, yields a
      typed error that names the file and the reason. It does not panic and it
      does not fail the whole set — the other files in the directory still load.
- [ ] Durations accept the `45m` and `10s` forms.
- [ ] Parsing is unit-tested without a filesystem or a timer, BDD-named — e.g.
      `it_defaults_the_interval_to_ten_seconds`,
      `it_rejects_a_file_with_no_check`.

## Review notes

### Round 1 — `review-799ffe-eae5381d` — VERDICT: needs-changes

Reviewer re-ran the gates empirically: 13 tests green, `clippy -D warnings`
clean. Both confirmed. No scope creep into running or timing.

1. **Overflow panic — `heartbeat.rs:71` — BLOCKING.** `mins * 60` is unchecked
   `u64` multiplication. Any value above `u64::MAX / 60`
   (307,445,734,561,825,860) panics in debug and wraps silently in release.
   Reachable: `timeout: 307445734561825861m` is valid YAML holding a valid
   `u64` that overflows on multiply. The card's contract says a bad file must
   yield a typed error and must not panic. Fix with
   `checked_mul(60).ok_or_else(...)`. The same risk exists on `interval`.
   No negative test covers it.
2. **Block-scalar test is not verbatim — `heartbeat.rs:287-312`.**
   `it_reads_block_scalar_check_verbatim` uses `contains()`, not `==`, and
   never asserts trailing-newline preservation. The round-trip test at line 210
   only checks `contains("pgrep")`, so the `|` inside `'rustc|cargo'` is never
   confirmed byte-for-byte. The test name promises verbatim; the assertions do
   not deliver it.
3. **`load_heartbeats` partial-failure path has no unit test.** The "must not
   fail the whole set" criterion is satisfied by the code but entirely
   untested — all 13 tests exercise `parse_heartbeat` only, and
   `load_heartbeats` is never called from a test. Separately, line 154's
   `filter_map(|e| e.ok())` silently drops `DirEntry` enumeration errors
   without adding to `errs`, inconsistent with how file-read errors surface.
4. **Missing negative duration tests (minor).** Uncovered: empty string,
   whitespace-only, and the overflow value from finding 1. The timeout/check
   error tests (lines 240, 247) do not assert `err.file`, unlike the label and
   YAML-error tests.
5. **`serde_yaml` 0.9 is deprecated — follow-up, not blocking.** Resolves to
   literally `0.9.34+deprecated`; dtolnay archived the crate in 2024. Low
   immediate risk for a read-only parser over version-controlled files in a
   sandboxed guest, but no upstream security fixes will land. Filed separately.

### Round 2 — `review-799ffe-eae5381d` — VERDICT: accept

All four round-1 findings verified fixed by the same reviewer, which re-ran the
gates itself rather than trusting the implementor's claims.

1. **Overflow — FIXED.** `checked_mul(60).ok_or_else(...)` at
   `heartbeat.rs:71-74`. Both `timeout` and `interval` route through
   `parse_duration`, so both paths are guarded; the `s` suffix does no
   multiplication and `Duration::from_secs` accepts any `u64`. Covered by
   `it_rejects_a_duration_that_overflows_on_conversion_to_seconds`.
2. **Verbatim block scalar — FIXED.** `assert_eq!` against the exact byte
   string, trailing newline included.
3. **`load_heartbeats` — FIXED.** `DirEntry` errors now push into `errs`. Three
   new tests; the partial-failure test asserts `heartbeats.len() == 1` and
   `errors.len() == 1`, so it genuinely proves one bad file does not sink the
   set.
4. **Negative duration tests — FIXED.** Empty, whitespace-only and overflow
   inputs covered; `err.file` asserted on the no-timeout and no-check
   rejections.

Non-blocking nit carried forward, deliberately not fixed: the test-only
`TempDir` helper keys its path on the PID, so a panic that leaks a directory
plus an immediate PID recycle could let a later run see stale files. Reviewer
judged this acceptable for a test helper.

Gates observed by the reviewer: 18 tests pass (was 13), `clippy -D warnings`
clean, `cargo fmt --check` exit 0. Fix commit touches only `heartbeat.rs` — no
board writes, no scope creep.

**Reviewer reported a menu gap:** it had to fall back to raw `cargo` because the
project menu exposes no Rust test/lint command. Filed separately.
