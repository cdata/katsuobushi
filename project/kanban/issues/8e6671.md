## What to build

Give the board an icebox: a note that exists with no `[[<id>]]` card on the
board. The icebox is **derived**, not a stored field and not a lane — a note is
iced exactly when no board card references it. This lets a contributor file an
idea by adding one new file, with no `BOARD.md` edit and so no collision.

- **File in.** `project new --icebox` writes the note only and adds no card.
  Plain `project new` is unchanged (still adds a To-do card).
- **See it.** `project status --icebox` lists the iced notes — id, title, labels
  — and nothing else. It composes with `--label`
  (`project status --icebox --label=PDD001`). Plain `project status` stays
  board-only.
- **Lint reclassifies the orphan.** A note with no board card is now normal, not
  suspect. The `orphan-note` check drops from `warn` to an `info` inventory line
  (e.g. `info: 2 notes in icebox: 8be736, 4a1c90`) and never fails the gate.

The `status set` edges that move a note in and out of the icebox
(promote/shelve/cancel) are a separate card.

### Seam (verified against the tree)

- `--icebox` on `project new`: gate the single `board.insert_card(Status::Todo,
  ...)` call (`new.rs:87-89`) — when set, skip it (and the board write). Add
  `pub icebox: bool` to `NewArgs` (`new.rs:18-27`) and the clap `New` variant
  (`main.rs:66-92`), wire through `mod.rs:46-71`.
- `--icebox` on `project status`: add a bool to `StatusArgs`
  (`main.rs:123-137`); thread into `query::show` (`mod.rs:105-113`). Derive the
  icebox by **set difference**: notes under `issues/` minus the ids the board
  references (`board_ids`). Keep it out of the note. Compose with the `--label`
  filter from card 01.
- Lint: the `orphan-note` `warn` at `lint.rs:206-211` becomes `info`. Add an
  `info(...)` constructor mirroring `warn`/`error` (`lint.rs:61`) and an arm in
  `human` (`lint.rs:270-276`); the `has_error` gate (`lint.rs:249`) already
  ignores non-error severities, so exit stays 0.
