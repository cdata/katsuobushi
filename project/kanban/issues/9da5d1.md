## What happened

`BOARD.md` has three writers with incompatible serializations, so opening the
board in the Obsidian Community Kanban plugin re-introduces format drift:

- **katsuctl `project` CLI** (v0.3.4+): `kanban-plugin: basic`, single-blank
  empty lanes, `---` separator, prettier-stable. Preserves the frontmatter
  verbatim.
- **prettier** (`markdown format` gate): the canonical form the CLI matches.
- **Obsidian Kanban plugin**: writes its own form — `kanban-plugin: board`,
  blank-line padding (double-blank lanes), its own separator. Not
  prettier-stable and not configurable to match.

Opening in Obsidian rewrites `BOARD.md` into the plugin's shape, which then
fails a prettier gate that globs the board and disagrees with the CLI. The
plugin's serializer is fixed, so the three cannot be reconciled — one writer
must stop touching the file. (v0.3.4 already gitignored `.obsidian/`, the
~1MB per-vault editor state that also appears on open.)

## Suggested fix

`BOARD.md` is machine-managed structured data, not prose. Take it out of the
prettier gate (exclude `**/BOARD.md`; keep `issues/*.md` gated — those are real
prose Obsidian doesn't reformat). This kills the CI/gate failure regardless of
which tool wrote last. Apply in this repo's flake `markdown.include` and
document it for `lib.markdown` / `lib.project` consumers (the churn bit
consumers like cdata/arcanabasis whose gate globbed `project/kanban/**`).

Optional, deeper (a separate decision): realign the CLI writer to the plugin's
exact on-disk format (double-blank lanes, `***`) so CLI- and Obsidian-written
boards round-trip byte-identically — zero cosmetic churn, but reverses part of
v0.3.4's formatting and couples the CLI to the plugin's serializer. The
archive-tolerance fixes are format-independent and stay either way.

## Acceptance criteria

- [ ] `BOARD.md` is excluded from the prettier `markdown format` gate; opening
      the board in Obsidian no longer fails `markdown lint` / the flake check
- [ ] `issues/*.md` stay gated (prose formatting preserved)
- [ ] The exclusion is documented for `lib.markdown` / `lib.project` consumers

## Review notes

**Peer review (independent agent), 2026-08-04 — blocking finding, fixed.**

The staged ignore file was namespaced by configuration `name` only, but
`<name> format` and `<name> lint` share a `name` — so two overlapping runs
shared one path and the first to finish deleted it out from under the second.
Prettier does **not** error on a missing `--ignore-path`; it exits 0 having
ignored nothing, so the losing `format` run would silently rewrite every
excluded file, including the machine-managed `BOARD.md` this card exists to
protect.

Fixed: the staged name carries the pid, and a missing staged file is now a hard
error rather than a silent no-op. Verified with concurrent `format` runs.
`.prettierignore.*` added to `.gitignore` for SIGKILL litter.
