## What to build

F1 + F1c of `design/warm-artifacts.md` — the core change. `lib.rust` gains
`seedArtifacts` (a list of `depsFor`-shaped `{ target?, profile? }` entries; `[]`
disables), and the bundles it names are extracted into `CARGO_TARGET_DIR` on
shell entry.

`rustEnvironmentHook` (`lib/rust/default.nix:128-130`) is the seam — it already
owns `CARGO_TARGET_DIR` and runs on every shell entry, host and guest alike. It
grows one line calling a generated script that:

1. Reads the stamp at `$CARGO_TARGET_DIR/.katsuobushi-seed`.
2. Compares it to the bundle's store path, baked in at eval time. Equal →
   return. A string compare, so the steady-state cost is milliseconds per entry.
3. On mismatch, validates alignment against the bundle's manifest (blocker
   333168), then calls crane's `inheritCargoArtifacts` — reuse it, it takes
   explicit args precisely so it is not welded to the phase that normally calls
   it — writes the stamp, and registers a GC root.

`KATSUOBUSHI_NO_SEED=1` skips it entirely.

**F1c — the GC root is not optional.** Crane symlinks `deps/*.rlib` / `*.rmeta`
into the store rather than copying (60-70% of the bundle by its own comment), so
a long-lived interactive target dir breaks outright if the bundle is collected.
Register a root for the bundle seeded from, and drop the previous root when
re-seeding.

## Scope change from b2c8e5 (2026-08-05) — read this first

The experiment measured **seeding alone as a complete no-op**: a target dir
seeded from the bundle re-checked every third-party crate, byte-for-byte as slow
as an empty dir (19.5 s vs 19.3 s cold). Full reuse (1.1 s, workspace crates
only) happened *only* when the shell's cargo also resolved dependencies through
the **same vendored source replacement** the bundle was built against — crane's
`cargoVendorDir/config.toml` and its `[source.crates-io] replace-with`.

So the untar is the cheap half; the vendor config is the load-bearing half.
Three things this adds, detailed in `design/warm-artifacts.md` §10.2:

1. **Install the vendor config without hijacking `CARGO_HOME`.** Overriding it
   wholesale hides the user's `~/.cargo/config.toml` and registry credentials.
   Candidates: a generated `CARGO_HOME` that `include`s theirs; the project's own
   `.cargo/config.toml` (invasive, tracked); or per-key env overrides if cargo's
   env mapping can express a dynamically-named `[source.…]` block. **Settle this
   first — it is unverified.**
2. **`KATSUOBUSHI_NO_SEED=1` must restore a stock cargo**, dropping the vendor
   config and not just skipping the untar. A seeded shell is frozen to
   `Cargo.lock`, so `cargo add` / `cargo update` behave differently.
3. **The F1a manifest (333168) gains a vendor-dir field** — bundle and vendor
   config from different evaluations are as mismatched as divergent `RUSTFLAGS`.

## Acceptance criteria

- [ ] `seedArtifacts` accepted; `[]` (or the env escape hatch) is a no-op
- [ ] The vendor config reaches the shell's cargo, by a mechanism that preserves
      the user's own cargo config and credentials
- [ ] `KATSUOBUSHI_NO_SEED=1` yields a completely stock cargo (no vendor config)
- [ ] A cold target dir is seeded once; a second shell entry is a no-op stamp hit
- [ ] Misaligned bundle refuses to seed and prints the diff, per 333168
- [ ] GC root registered for the seeded bundle; prior root dropped on re-seed
- [ ] Measured: a seeded shell re-checks workspace crates only (the arm-2 result,
      reproduced through the real `seedArtifacts` path rather than by hand)
- [ ] Verified in a sandbox VM: a dispatched agent's first build is warm

## Review notes

**From b2c8e5's peer review (2026-08-05) — correction to this card's F1c
premise.** "Crane symlinks `deps/*.rlib` / `*.rmeta` into the store" is **false
for the `target.tar.zst` bundle form this project produces**: the reviewer
counted 0 symlinks and 154 regular `.rmeta` files in a seeded target dir, because
the tarball path in `inheritCargoArtifacts` untars real files and never takes the
rsync/symlink branch. The GC-root argument for F1c is therefore weaker than
written — re-derive it (a GC root may still be wanted so the *bundle* survives
for re-seeding) rather than inheriting the symlink rationale unexamined.
