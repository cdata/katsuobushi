## What happened

`--until-report` defaults off everywhere — `sandbox start`, `sandbox
prompt`, and `sandbox dispatch` all take it as an opt-in flag, and
`rust/katsuobushi-controller/src/main.rs:425` / `:478` pin the default with
explicit asserts. Off means the drive returns the moment the agent yields:
a `TurnCompleted{reported: false}` surfaces the "stopped without reporting"
warning and **breaks** (`rust/katsuobushi-controller/src/sandbox/prompt.rs:499-510`),
instead of staying armed for the guest's auto-nudges or a late terminal
report.

For an *interactive* prompt that default is defensible — the operator is
watching and can re-prompt. For **orchestration flows** it inverts the
meaning of the command exiting: the orchestrator (or a human skimming) reads
"the command returned" as "the work concluded". Field case (2026-08
post-mortem, item 4): the flag was omitted on both reviewer launches, so a
reviewer that paused mid-cold-build read as complete — the review verdict
was judged from a drive that had simply disarmed. The skills document the
flag as opt-in (`plugins/katsuobushi/skills/sandbox/SKILL.md:226-227`,
`project-orchestration/SKILL.md:190-192`), which makes forgetting it the
default outcome precisely where it matters most.

The guest's auto-nudge machinery (bounded re-prompts before resolving
`ended-unreported`) exists exactly to recover unreported turn-ends — but the
host only benefits if the drive stays armed to hear the recovered report.

## Suggested fix

Flip the default where the caller is an orchestration flow, keep the
interactive default as-is:

- **`sandbox dispatch`**: default `until_report = true` (it already threads
  the flag through `dispatch.rs:37,54`). A dispatched card's drive should
  end only on a terminal report, transport death, or delivery exhaustion.
  Add `--no-until-report` as the escape hatch.
- **`sandbox start --agent --prompt …`**: same default flip — a first-turn
  directive is dispatch-shaped, not interactive. The tail-called `prompt`
  already inherits the flag (`start.rs:81-82`, `:866-880`).
- **`sandbox prompt`**: leave the default off (interactive use), but when a
  turn ends unreported without the flag, extend the existing warning with
  the recovery hint: re-run with `--until-report`, or check
  `turn-state.json` for a later `ended-ok` — nudges may still land a report
  after this process exits.
- Update both skills: document the new defaults, and rewrite the reviewer
  recipe in `project-orchestration` to note that the drive now stays armed
  by default (no flag to remember).
- Note the behavior change in CHANGELOG/MIGRATING (a dispatch that
  previously returned on an unreported yield now keeps waiting — callers
  that relied on the early return need `--no-until-report`).

## Acceptance criteria

- [ ] `sandbox dispatch` and prompted `sandbox start` stay armed across an
      unreported turn-end by default; `--no-until-report` restores the old
      behavior. CLI asserts/tests updated to pin the new defaults.
- [ ] Interactive `sandbox prompt` behavior unchanged, with the improved
      warning text.
- [ ] Skills, CHANGELOG, and MIGRATING describe the flip.

## Review notes

**Peer review (independent agent), 2026-08-04 — accepted with test gaps closed.**

AC 1 asked for tests pinning the new defaults. The clap-level defaults were
pinned, but the actual flip — `!no_until_report` in the subcommand dispatcher —
was not: inverting that `!` left the whole suite green. AC 2's improved warning
text was unasserted anywhere.

Fixed: the polarity is now a named `armed()` function with a test, and
`stopped_message` has a test covering both recoveries it must name.
