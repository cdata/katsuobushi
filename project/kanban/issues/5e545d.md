## What to build

_As an orchestrator, I run `sandbox status` and read one line per instance. I
know which VMs to leave alone, which to fetch from, and which to look at._

`sandbox status` shows three things for each instance:

- **The work state**, with the flag folded in as `Active (Late)`, plus the label
  and the beating duration of the heartbeat that carries it. For example
  `Active — Compiling (34 units), 12m of 45m`.
- **The last incremental report**, when the agent chose to send one. These stay
  voluntary. The status shows the newest one and its age.
- **The nudge count**, as spent over budget. For example `idle — nudged 3/5`.

The four readings an operator gets:

| Work state      | What is true                            | What a person does      |
| --------------- | --------------------------------------- | ----------------------- |
| `finished`      | The agent reported `done` or `blocked`. | Fetch the branch.       |
| `active`        | Work runs. The label says what.         | Leave it alone.         |
| `active (late)` | Work runs past its own declared bound.  | Look. Something wedged. |
| `idle`          | Nothing runs.                           | Read the nudge count.   |

## Acceptance criteria

- [ ] One instance shows all three facts in one reading: the work state with its
      label and duration, the newest voluntary report with its age, and the
      nudge count over the budget.
- [ ] A late heartbeat renders as `Active (Late)`, not as a fourth state.
- [ ] An instance that has sent no voluntary report renders without one, and
      does not render an empty field.
- [ ] Every fact in the human output is also present in `--json`.


## Note from the `f7de81` review

The guest already writes all seven fields into `work-state.json` — `work_state`,
`is_late`, `carrying_label`, `carrying_duration_secs`, `last_report_text`,
`last_report_at` and `nudge_count`. The host does **not** read three of them:
`WorkStateRecord` in `rust/katsuobushi-controller/src/sandbox/status.rs:698`
deserializes only four fields, so serde silently drops `nudge_count`,
`last_report_text` and `last_report_at`.

So the data this card must render is already on disk. The work is host-side —
widen `WorkStateRecord` and render — not another round of guest plumbing.

## Review notes

### Round 1 — `review-5e545d-865a5ce3` — VERDICT: needs-changes

Gates observed by the reviewer: 574 tests pass (463 + 55 + 46 + 10), lint clean.

**BLOCKING — `lastNoteAge` is a pre-formatted string in `--json`, not a raw
value.** The commit message claims the four new `InstanceView` fields "carry the
raw values into `--json`". That is true of `nudgeCount` and `nudgeBudget`
(numbers) but false of `lastNoteAge`, which serialises as `"5m ago"` — a
humanised string computed at status-read time. It goes stale immediately and
cannot be recomputed or compared, so a machine consumer cannot answer "is the
note older than ten minutes?" from `--json` alone. The raw RFC-3339
`last_report_at` is read from `work-state.json` but never plumbed through
`WorkStateSummary` into `InstanceView`. Sites: `WorkStateSummary` (~`:768`)
missing a `last_note_at`; `read_work_state` (~`:816`) computes the age but drops
the raw value; `InstanceView` (~`:112`) serialises the formatted string.

**The `WORK` column question is resolved — it is correctly wired.** The header
is in the array (`status.rs:465`) and every row appends
`v.work_state.as_deref().unwrap_or("-")` (`:488`), pinned by
`it_shows_work_state_column_in_the_list_table`. The host not seeing it is
explained: `run_list` short-circuits on `views.is_empty()` and prints "No active
sandboxes" instead of rendering the table at all. With instances present the
column appears, showing `-` for a pre-feature instance.

**Rendering confirmed by the reviewer through the unit tests:**

```
Active        Active — agent-work, 42s   /   Active — agent-work, 2m
Active Late   Active (Late) — agent-work, 10m
Idle          Idle        /   Idle — nudged 3/5
Note line     note:       building the feature (3m ago)
WORK cell     Active — compile, 5m   /   -
```

- **Late is a flag, never a fourth state** — `"active" if record.is_late =>
  "Active (Late)"` (`:789`), no bare `Late` branch.
- **The absent-note case is clean** — guarded by `if let Some(note)` (`:534`);
  no label, no dangling field, no `None`/`null` leak.
- **`nudge_budget` does not drift** — populated from `ctl.max_nudges`
  (`server.rs:1199`), the same variable the nudge logic tests against
  (`t.nudges < max_nudges`, `:516`). No second hardcoded 5.
- **Degradation is safe** — all four new host-side fields carry
  `#[serde(default)]` (`:737-744`), so an old-format `work-state.json` written
  by a pre-feature guest still parses.
- **Tests are not clock-sensitive** — the note test pins `now()` to a fixed
  instant against a fixed `lastReportAt`.

**Non-blocking design note:** the nudge count is folded into the human line for
`idle` but appears only in `--json` for `active`. The reviewer judged this
defensible — nudges fire only during idle, so the count is actionable only there
— and it matches the PDD's own example. Recorded rather than changed.
