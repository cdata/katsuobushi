## What to build

The `implement` skill: a scheduler that keeps a sandbox swarm hot on one work
thread and drives its cards to `ready`. A new skill at
`plugins/katsuobushi/skills/implement/SKILL.md` (loads as `katsuobushi:implement`).
It is a **driver**, not a new engine — it runs `sandbox dispatch/fetch/prompt` and
the report bridge from the `project-orchestration` skill.

Behaviour (PDD002 Body):

- **A work thread is a label.** It may pull a card's out-of-label blocker into
  scope only after **asking the person**.
- **Open with a negotiation:** concurrency budget (how many sandboxes, vCPUs each;
  ceiling = all building at once must not oversubscribe cores), roles (how many
  implementors/reviewers), threads (which labels).
- **Each card gets its own warm implementor + reviewer VM pair**, kept warm across
  the review bounce loop; both stop when the card hits `ready`.
- **Parallelism counts active (not paused) sandboxes;** cards in flight may exceed
  the active budget.
- **Scheduler priority:** fill a free slot with in-flight review-loop work first
  (a bounced implementor, then a reviewer with a pushed revision), only then the
  next available card. Include the pseudocode.
- **A bounce reuses the same reviewer** via a push to its `sync.git` mirror — never
  a fresh reviewer VM.
- **Stops at `ready`; never accepts.** When the thread has no available work, it
  reports and stops (does not idle on `ready` cards).
- **Thread selector** is `project status --available --label=<thread>`.

Reference (don't restate) the `project-orchestration` and `sandbox` skills. Match
the house voice/length.

## Acceptance criteria

- [ ] `plugins/katsuobushi/skills/implement/SKILL.md` exists with valid
      frontmatter, loading as `katsuobushi:implement`.
- [ ] The skill negotiates budget/roles/threads and schedules per-card warm
      implementor+reviewer VM pairs, with the in-flight-first scheduler + pseudocode.
- [ ] A bounce reaches the same reviewer via a mirror push, not a new VM.
- [ ] It finds its thread with `project status --available --label=<thread>` and
      asks before pulling an out-of-label blocker into scope.
- [ ] It stops a card at `ready` and never runs `project status set <id> accepted`.
- [ ] `markdown lint` clean; plugin/skill validators pass.
