## What to build

F3a + F4 of `design/warm-artifacts.md` — the text-only half, which pays off even
if the F1 seeding work never lands.

- **The obligation (F3a).** Both the guest contract (`lib/sandbox/default.nix`,
  the agent-mode instructions the guest renders) and the `project-orchestration`
  skill state, in the imperative: consult the project menu (`showMenu`) before
  running any build/test/run command; use the project's own command when one
  exists; reach for raw `cargo` / `nix build` only when the menu has no command
  for the need — and **report it when you do**, because a missing menu command is
  a gap in the project, not a licence to improvise.
- **The folklore (F4).** The orchestration skill's reviewer-directive template
  currently teaches "first build cold-compiles and takes minutes", which budgets
  twenty minutes for the wrong command. Point the reviewer at the menu instead.
- The `sandbox` skill's "raise `progressStallSecs`" advice should first ask
  whether the project warms at all — the timeout is the workaround, not the fix.
- The orchestration skill's `.dispatch-instructions.md` guidance inverts: build
  and test commands belong in the **menu** (executable and discoverable); the
  instructions file carries only what the menu cannot express — acceptance gates,
  VCS discipline, reporting rules.

## Review notes

**Peer review 2026-08-05 — NEEDS CHANGES (blocking).**

1. `lib/sandbox/default.nix:576-582` — the agent-contract paragraph said to read
   "the command table the dev shell printed on entry (or run `showMenu`)".
   Neither exists in agent mode. The agent is launched at
   `lib/sandbox/default.nix:1699` as `bash -lc '… cd <workspace> && exec claude
   …'` — never through `nix develop` — so nothing was printed, and `showMenu` is
   a bash function defined only by the dev-shell hook
   (`lib/menu/default.nix:451-455`); the `menu` binary is likewise only on the
   dev-shell PATH, and the guest's `environment.systemPackages` (`:1299-1338`)
   does not carry the project's menu commands. A dispatched agent that obeys the
   contract gets `command not found`, and the next sentence then licenses the raw
   `cargo` fallback this card exists to prevent. Fix: point at
   `nix develop -c menu`. Reviewer evidence: `env -i … bash -lc 'type -t
   showMenu'` → NOT DEFINED. (A naive check from inside an existing `nix develop`
   falsely reports it present, because `export -f showMenu` propagates.)
2. `lib/sandbox/default.nix:579-580` and
   `plugins/katsuobushi/skills/project-orchestration/SKILL.md:201-202` — "those
   commands are wired to the artifacts this VM already has" was asserted as fact
   about an arbitrary consumer's menu. False for this repo (`flake.nix:226-236`
   builds the menu from markdown/project/sandbox groups only — no Rust
   build/test command at all), and false everywhere until F1 lands. State it
   conditionally, as the `sandbox` SKILL.md:148 edit already does.

The interactive README text at `lib/sandbox/default.nix:494-503` is accurate as
written (it says to run `nix develop` first) and needed no change.
