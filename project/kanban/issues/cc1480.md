## What to build

The flake's menu currently exposes only `markdown`, `menu`, `project` and
`sandbox`. It has no command that builds, tests or lints the Rust workspace, so
there is nothing to steer a dispatched agent to.

Two concrete consequences are already on the record. The peer reviewer on card
`799ffe` had to fall back to raw `cargo` and said so in its report, exactly as
the orchestration contract asks it to. And `project/kanban/.dispatch-instructions.md`
compensates by hardcoding `nix develop -c cargo test -p ...`,
`nix develop -c cargo clippy -p ... -- -D warnings` and `nix develop -c cargo fmt`
in prose — a copy that will drift from the commands that actually exist, and that
names one crate at a time so every new crate needs the file edited again.

Build/test commands belong in the menu, where they are executable and
discoverable (`nix develop -c menu` from anywhere, `showMenu` inside the shell),
and where the project's artifact sharing is actually wired. The prose file should
be left to carry only what the menu cannot express.

## Acceptance criteria

- [ ] `nix develop -c menu` lists a Rust build command, a test command and a lint
      command.
- [ ] The lint command is the acceptance gate — it fails on any clippy warning.
- [ ] The test command covers the whole workspace, not one named crate, so a new
      crate is picked up without editing anything.
- [ ] A formatting command is available and its check form is usable in CI.
- [ ] `project/kanban/.dispatch-instructions.md` no longer hardcodes raw `cargo`
      invocations; it points at the menu instead.
- [ ] Running each new menu command from a clean checkout succeeds.
