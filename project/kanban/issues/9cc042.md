## What to build

The `sandbox` command exposes a hand-maintained allowlist of subcommands that
can drift from the Rust CLI without any check noticing.

`lib/sandbox/default.nix` defines `menuCommands` with one entry per verb —
`start`, `dispatch`, `prompt`, `status`, `fetch`, `stop`, `attach`,
`screenshot`. Anything absent falls through to `Unknown subcommand`
(`lib/menu/default.nix` line 252). The Rust CLI declares its own list as
`SandboxCommand` variants in `rust/katsuobushi-controller/src/main.rs`. Nothing
ties the two together.

Card `69d1df` added the `deliver` verb to the Rust CLI and to the `sandbox`
skill, but not to `menuCommands`. The result shipped to `ready`:
`katsuctl sandbox --config <spec> deliver` works, `sandbox deliver` answers
`Unknown subcommand: deliver`. Two later cards then documented a command that
errors.

Nothing caught it. `rust test` and `rust lint` cover the crate; the allowlist is
Nix data, so the two stay green while they disagree. The card's peer reviewer
verified the Rust routing, `--branch`, and `--json`, all correct at that layer,
and read "lives beside the other sandbox verbs" as the `SandboxCommand` enum —
where `Deliver` does sit between `Fetch` and `Stop`.

Two parts, and the second is the point:

1. Expose `deliver` through the `sandbox` wrapper, beside `fetch`.
2. Add a check that **fails** when the wrapper's subcommand set and the Rust
   `SandboxCommand` set diverge. Wiring one verb fixes one verb; the seam is
   what let this reach `ready` unnoticed, and the next verb will take the same
   path.

The check belongs where the existing gates run, so a divergence breaks the build
rather than waiting for an operator to type the command.

## Acceptance criteria

- [ ] `sandbox deliver` runs the verb, and `sandbox` lists it beside `fetch`
- [ ] A check fails when a `SandboxCommand` variant has no wrapper entry
- [ ] That check also fails in the reverse direction — a wrapper entry with no
      Rust subcommand
- [ ] The check is wired into the project's existing gates, and its failure
      message names the offending verb and both places to look
- [ ] Removing `deliver` from `menuCommands` makes the check fail (prove it,
      then restore)
