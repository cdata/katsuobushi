## What happened

`journal_event` (`rust/katsuobushi-controller/src/sandbox/prompt.rs`) stamps
each entry via `now_rfc3339(host)`, which shells out to `date` through the host
seam. That is one fork per journaled event, including every non-terminal
`working` report.

Reports are rare, so this is not a hot path — but the clock seam exists so the
timestamp is testable, not because a subprocess is required, and a chatty agent
makes it needless churn.

## Suggested fix

Cache the offset once per drive, or widen the host clock seam with a
non-subprocess implementation, keeping the seam (and its fake) intact for tests.

## Acceptance criteria

- [ ] A drive that relays N reports does not fork N `date` processes.
- [ ] The clock stays seamed — tests still control the timestamp.
