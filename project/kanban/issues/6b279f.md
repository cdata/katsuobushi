## What happened

The per-instance state dir is `chmod a+rwX`'d at launch
(`rust/katsuobushi-controller/src/sandbox/start.rs`, the share-root chmod) and
exported wholesale to the guest as a writable 9p share
(`lib/sandbox/default.nix`). Two files that the host presents as
**host-authored** now live in it:

- `reports.ndjson` — documented as host-side journaling of what the agent
  reported (card 60b91e).
- `directive.md` — the composed launch directive (card 1c3984).

A guest can write either. Hand-writing a `reports.ndjson` line makes
`sandbox status` render an arbitrary `last report:` verdict that no agent ever
sent, and rewriting `directive.md` changes what `sandbox prompt --redeliver`
delivers.

`turn-state.json` is guest-authored **by design** and is treated as advisory.
These two are not — the trust story regresses quietly, because the rendering
is identical either way.

## Why it matters

The point of the report journal is answering "what did it conclude?" when the
stream is gone. If the answer is forgeable by the thing being reviewed, a
compromised or merely buggy guest can launder a verdict past an operator who
believes they are reading host-side state.

## Suggested fix

Move host-authored state out of the 9p share into a sibling directory the guest
never mounts (e.g. `<stateGlob>/<inst>/host/`), leaving the share for genuinely
shared files. Failing that, mark guest-writable provenance explicitly in
`sandbox status` output so an operator can tell the two apart.

## Acceptance criteria

- [ ] A guest cannot write the file that backs `sandbox status`'s
      `last report:` line, or the file `--redeliver` reads.
- [ ] Existing instances degrade gracefully (a missing host-side dir is not an
      error).
