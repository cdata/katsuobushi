## What to build

The sandbox swarm leaves vestigial state behind in local history, and nothing
reaps it. As instances accumulate across a work session, so do:

- per-instance `sandbox/<name>` local branches,
- the `refs/katsuobushi/<name>` tracking refs (added by PDD001's fetch change),
- per-instance `sync.git` bare mirrors and state dirs,
- abandoned jj working-copy commits left by each landing (`jj new` strands the
  prior `@`).

Prune these proactively as work is accepted, instead of letting them pile up.

**Proposed direction (to be settled in a design):**

- The safe trigger is a card reaching a **terminal** state (`accepted` or
  `cancelled`). PDD001 keeps `sandbox/<name>` as the revert artifact only until
  the card is accepted, so acceptance is exactly when the instance's refs and
  mirror become dead weight.
- A `sandbox prune` (gc) reconciles live refs + mirrors + state dirs against the
  board. It reads the board read-only (the same one-way seam `dispatch` uses),
  finds instances whose card is terminal, and removes only their state. It never
  touches a ref for a live (non-terminal) card.
- Trigger it at the tail of an `implement` session and/or as an explicit
  maintenance command.
- Leave jj op-log / dangling-commit pruning (`jj abandon`, `jj util gc`) to a
  later, careful pass. Reaping git refs and mirrors is low-risk. Touching the op
  log is not.

This card is in the **icebox** (note exists, no board card) pending a design.
Candidate for its own PDD.

## Acceptance criteria

- [ ] A design settles the prune mechanism, its trigger, and its safety rule
      (prune only instances whose card is terminal).
- [ ] Vestigial per-instance git refs and mirrors are removed once their card is
      accepted or cancelled.
- [ ] The prune never removes refs or mirrors for a live, non-terminal card.
- [ ] jj op-log pruning is explicitly scoped in or out with its risk stated.
