## What to build

The sandbox swarm leaves vestigial state behind in local history, and nothing
reaps it. As instances accumulate across a work session, so do:

- per-instance `sandbox/<name>` local branches,
- the `refs/katsuobushi/<name>` tracking refs (added by PDD001's fetch change),
- per-instance `sync.git` bare mirrors and state dirs,
- abandoned jj working-copy commits left by each landing (`jj new` strands the
  prior `@`).

Prune these proactively as work is accepted, instead of letting them pile up.

**Proposed direction (to be settled in a design):**

- The safe trigger is a card reaching a **terminal** state (`accepted` or
  `cancelled`). PDD001 keeps `sandbox/<name>` as the revert artifact only until
  the card is accepted, so acceptance is exactly when the instance's refs and
  mirror become dead weight.
- A `sandbox prune` (gc) reconciles live refs + mirrors + state dirs against the
  board. It reads the board read-only (the same one-way seam `dispatch` uses),
  finds instances whose card is terminal, and removes only their state. It never
  touches a ref for a live (non-terminal) card.
- Trigger it at the tail of an `implement` session and/or as an explicit
  maintenance command.
- Leave jj op-log / dangling-commit pruning (`jj abandon`, `jj util gc`) to a
  later, careful pass. Reaping git refs and mirrors is low-risk. Touching the op
  log is not.

This card is in the **icebox** (note exists, no board card) pending a design.
Candidate for its own PDD.

## Acceptance criteria

- [ ] A design settles the prune mechanism, its trigger, and its safety rule
      (prune only instances whose card is terminal).
- [ ] Vestigial per-instance git refs and mirrors are removed once their card is
      accepted or cancelled.
- [ ] The prune never removes refs or mirrors for a live, non-terminal card.
- [ ] jj op-log pruning is explicitly scoped in or out with its risk stated.


## The design this card was waiting for (from the `c1a6e1` planning pass)

This card was iced "pending a design". `c1a6e1` supplies it.

Under the settled landing contract the host **never rewrites guest commits** — it
duplicates them onto host history — so `sandbox/<inst>` only ever holds pure
guest history with **no host descendants**. That removes the hazard that made
pruning risky: deleting the ref at acceptance cannot strand host work, because
none of the host's work hangs off it.

Two consequences for this card's scope:

- The trigger stays as proposed: a card reaching `accepted` or `cancelled`. What
  changes is that the prune is now provably safe rather than needing a
  descendant check first.
- `refs/katsuobushi/<name>` is no longer the ref to reap. `c1a6e1` moves the
  fetched ref to a remote-bookmark namespace; reconcile this card's list against
  whatever namespace that lands on rather than against the historical one.

The abandoned-working-copy-commit item in this card's list overlaps `9344ec`,
which owns commit descriptions and attribution. Keep the split: this card reaps
**refs, mirrors and state dirs**; `9344ec` handles what the landing procedure
leaves in the commit graph.

Blocked on `c1a6e1`.

## Review notes

### Round 1 — `review-c72eb6-46c73967` — VERDICT: needs-changes

Gates: 593 tests pass, lint clean.

**Every skip path was traced and every one fails closed** — the property that
matters most for a command that deletes:

| Situation | Behaviour |
| --- | --- |
| Card in `needs-review` | skipped |
| Card in any other active lane (`in-progress`, `ready`) | skipped |
| Card absent from the board (icebox) | skipped |
| Board missing or unreadable | error propagates **before** any deletion |
| Malformed card note (no parseable wikilink) | never matches, skipped |
| Instance name not exactly `card-` + 6 lowercase hex | skipped |
| Empty instance name | skipped before any deletion |

**The board seam is genuinely read-only** — `&Board` is passed as a shared
reference and every mutating method requires `&mut`, so the board text is never
written back.

**Path safety is clean.** `list_dir` returns basenames only, and the id must be
exactly 6 lowercase hex, so no crafted name can traverse out of the state root.
Removal is recursive but bounded to the instance's own directory.

**BLOCKING — reviewer instances are skipped entirely.** Only `card-<id>`
instances are considered, but every peer-review VM is `review-<slug>-<hash>`. The
card's own criterion says *"vestigial per-instance git refs and mirrors are
removed once their card is accepted or cancelled"* and never restricts that to
implementors. The reviewer's arithmetic is the point: a card with two review
rounds has **one** implementor instance and **two** reviewer instances, so the
reviewer state is the majority of the debris this card exists to reap.

**Minor findings, recorded:**

- A ref-delete spawn failure is silently swallowed — a git IO error is treated as
  "ref already absent", so the dir is removed and the stale ref is never retried
  on a re-run.
- If the state dir is a regular file rather than a directory, the error
  propagates and aborts the whole prune; recoverable only by hand.
- **No liveness check.** Accepting a card while its VM still runs would delete
  the state dir under a live QEMU. Mitigated by the workflow (instances are
  stopped at `needs-review`), and `stop` has the same gap — worth documenting
  rather than fixing here.
- **No test for a `needs-review` card specifically** — the most dangerous
  near-miss, one step from acceptance. The code is correct because all non-archive
  lanes share a path, but the safety coverage is undocumented.

### Round 2 — implementor revision

Extended prune to reap reviewer instances (`review-<card-id>-<8hex>`) alongside
implementors. **Design choice: made the naming contractual** — the
`project-orchestration` skill now states the reviewer `--name` slug **must** be
the card id (`SKILL.md:109`), on the grounds that this is already the established
convention and avoids adding metadata to `instance.json`. Fail-closed preserved:
any slug that will not parse as 6 hex is skipped.

Also fixed: git spawn IO errors now propagate rather than being swallowed as
"ref absent", leaving the state dir for a retry; a malformed state-dir entry is
reported and skipped instead of aborting the whole prune; a
`it_skips_a_card_in_needs_review_lane` test was added; and the liveness gap is
documented in the module doc as directed.

606 tests, lint clean. Landed and re-authored immediately, per `9344ec`.

**Concern referred to the reviewer — the new contract conflicts with real
practice.** This session created **`review-850ce4b-dc5d1b02`**: when a card
needed a *second, fresh* reviewer after the first had already disproved a fix, I
named it `review-850ce4b` to distinguish it from the paused `review-850ce4`. Its
slug is seven characters and will not parse as 6 hex, so under the new rule that
instance is skipped **forever** — silently, by the fail-closed path.

So the contract is being introduced against practice that already deviates, and
the deviation was deliberate: there is no documented way to run two reviewer
instances for one card, which the warm-pause workflow otherwise encourages. Either
the contract needs to accommodate a suffix, or the orchestration skill needs to
say plainly that a second reviewer replaces rather than joins the first.

### Round 2 — `review-c72eb6-46c73967` — VERDICT: accept

Gates: 606 tests (486 + 64 + 46 + 10), lint clean.

**Ruling on the naming contract: keep it strict.** The reviewer judged
`review-850ce4b` a **workflow error, not a design requirement**. The correct
protocol for a fresh second reviewer is
`sandbox stop --remove review-<card-id>` then start again with the *same* name —
the first is gone, the new one is fresh, and prune can reap it. The skill already
says to pause rather than remove; the missing piece is one sentence covering the
replace case, not a looser parser.

It also weighed the alternative and rejected it on merit: parsing a leading
6-hex prefix would map **any** `review-<6 hex>…` instance to a card, creating an
accidental-reap surface for a naming freedom that is not actually needed.

**Off-contract instances do need handling** — they fall through the
`instance_card_id → None` path silently. That is correct fail-closed behaviour,
but the debris is never reaped. Host checked: no off-contract state dirs remain,
since `review-850ce4b-dc5d1b02` was already removed. Filed as a follow-up.

**All four secondary fixes confirmed**, each against its test:

- Git IO errors propagate via `?` and leave both ref and state dir intact, while
  a non-zero exit (ref genuinely absent) still removes the dir — the distinction
  is real and both directions are tested.
- A malformed state dir is reported to stderr and skipped;
  `card-bbbbbb` is still pruned when `card-aaaaaa` fails.
- `it_skips_a_card_in_needs_review_lane` genuinely builds a board with the card
  in `## Needs Review` and asserts **no git call was issued** — not a renamed
  to-do test.
- The liveness gap is documented as a known limitation, not silently fixed.

**Path safety holds for the new name shape** — instance names come from
`list_dir` basenames, which cannot contain `/`, and the extracted card id is used
only for board lookup, never in a path.
