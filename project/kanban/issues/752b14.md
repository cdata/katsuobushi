## What happened

The launch recipe tees provisioning output with `tee -a`
(`rust/katsuobushi-controller/src/sandbox/start.rs`). A named instance keeps its
state dir across stop/start, so every relaunch appends another provisioning
transcript to the same `provision.log` with nothing distinguishing the runs.

Each transcript is small (a handful of `:::` lines), so this is untidiness
rather than a disk-space risk — but a long-lived named instance's log becomes
hard to read, and there is no marker for where one launch ends and the next
begins.

## Suggested fix

Either truncate per launch (each launch's provisioning is the interesting unit),
or keep appending but emit a run header (`::: launch <timestamp> <instance>`)
so the boundaries are greppable. Truncating loses history; the header keeps it.

## Acceptance criteria

- [ ] Relaunching a named instance leaves `provision.log` readable, with each
      launch's transcript clearly delimited or replaced.
