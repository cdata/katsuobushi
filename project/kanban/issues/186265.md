## What to build

The landing procedure duplicates a guest commit and then rewrites its metadata.
Both halves of that are avoidable, and the rewrite half is where every recent
failure has lived.

Four routes were measured on a scratch colocated repo. Only the last produces a
correctly attributed commit without a rewrite:

| Route | Author of landed copy | Rewrite? |
| --- | --- | --- |
| `jj duplicate -d @` | agent — preserved | yes, then `metaedit` |
| `jj duplicate` with `JJ_USER` / `JJ_EMAIL` set | agent — env ignored | yes |
| `git cherry-pick` + `commit --amend --reset-author` | owner | amend |
| **`git cherry-pick -n` + `git commit --reset-author -C <guest>`** | **owner** | **none** |

The last one stages the guest's diff without committing, then creates a fresh
commit: `--reset-author` makes it the owner's, `-C <guest>` reuses the guest's
message, and the content is the guest's diff. Verified end to end, including that
it signs automatically under the repository's existing `commit.gpgsign` config:

```
Good "git" signature for 0xcda7a@gmail.com with ED25519 key SHA256:xwJ9RePDr…
```

Why this is worth changing rather than patching around:

- **It removes a failure mode instead of working around one.** No rewrite means
  jj immutability never applies, so the silent no-op in `6d77aa` cannot fire, and
  the "verify the author afterwards because the command may lie" step disappears.
- **It dissolves a deadline.** `9344ec` needs a re-author-before-the-next-dispatch
  rule only because rewriting becomes impossible once a guest ref pins the commit.
  A commit born correct has nothing to race.
- **One operation replaces three.** Today: duplicate, `metaedit --update-author`,
  `sign`. Each needs `--ignore-immutable`, and each can silently do nothing.

Two things to settle during the work, neither yet exercised:

- **It is a git-side operation in a colocated jj repo.** The commit lands on git
  `HEAD` and jj imports it. How that interacts with jj's working-copy commit and
  `@` placement was not tested and must be.
- **What happens to `e7fd2b`'s dispatch guard.** Under this route there should be
  no un-attributed commits for it to catch. Keep it as a backstop — it still
  covers work landed by any other means — but say so, so a later reader does not
  delete it as dead code.

Unrelated but cheap, and worth folding in: `jj metaedit`, `jj sign` and
`jj describe` all accept `--ignore-immutable`, which is the supported flag for
what the procedure currently does with a `revset-aliases."immutable_heads()"`
override.

## Acceptance criteria

- [ ] The landing procedure in the sandbox skill lands a guest commit in one
      create, with no metadata rewrite.
- [ ] A landed commit carries the owner's authorship, the guest's message, the
      guest's diff, and a valid signature — verified, not asserted.
- [ ] The interaction with jj's working-copy commit and `@` placement is tested
      and documented.
- [ ] Any remaining rewrite step in the skill uses `--ignore-immutable` rather
      than a revset-alias override.
- [ ] The dispatch guard is retained with a note explaining what it still covers.


## Correction from PDD004 — the cherry-pick form in this card is wrong for a branch

`PDD004`'s read-through caught a defect in the route this card recommends.

`git cherry-pick -n <branch-tip>` applies **only the tip commit**. Measured in a
scratch repo: a two-commit branch staged one file, not two. On a bounced card
that lands the review fix and **silently drops the original work**.

The route is correct for landing a single commit. It is wrong as a way to land a
branch, which is what `PDD004` settles on — a card lands once, after review, as
one commit.

The correct form, also measured:

```
git merge --squash sandbox/<instance>
git commit -m "<type>(<scope>): <card title>"
```

This is simpler than the route this card proposed. It needs **no**
`--reset-author`: a new commit has no author to inherit, so it is the owner's by
construction, and it signs under the existing configuration. The message comes
from the card rather than from a branch commit, because a bounced branch carries
messages like "address review findings" that mean nothing in the owner's
history.

This card is superseded in substance by `PDD004`. Keep it open only for the
`--ignore-immutable` note, which stands on its own: `jj metaedit`, `jj sign` and
`jj describe` all accept that flag, and the procedure should use it rather than a
`revset-aliases."immutable_heads()"` override wherever a rewrite still happens.

## Cancelled — superseded by PDD004, and wrong on its own terms

Cancelled for two independent reasons, either of which is sufficient.

**It is wrong.** The route it recommends — `git cherry-pick -n <branch-tip>` —
applies the tip commit alone. On a bounced card it lands the review fix and drops
the original work. That defect stands regardless of any design decision.

**It is superseded.** `PDD004 Code Sharing Between Parties` settles landing as a
squash of the whole branch after review passes:

```
git merge --squash sandbox/<instance>
git commit -m "<type>(<scope>): <card title>"
```

That form is simpler than this card's and needs no author flag at all.

Nothing is lost. The one part of this card that stood on its own — that
`jj metaedit`, `jj sign` and `jj describe` accept `--ignore-immutable`, which is
better than a `revset-aliases."immutable_heads()"` override — is carried in
`6d77aa`.
