## What to build

F3c of `design/warm-artifacts.md`. Choosing the right command should not require
reading the flake. `lib.rust` offers helpers producing menu entries — with
consistent, honest descriptions — for the builders it already knows how to make,
so a project's menu says which commands are Nix-backed and share artifacts, and
which trade that away.

The test-archive replay is the one to steer agents toward: it needs no target
directory at all (it replays prebuilt binaries via `--workspace-remap`) and is
therefore the cheapest useful command in a cold VM.

Descriptions should read as what they are — the artifact-sharing path is the
norm and an impure/local-toolchain path is the exception, not a neutral trade.

## Acceptance criteria

- [ ] Helpers emit menu entries for the existing builders (incl. archive replay)
- [ ] Descriptions state the artifact-sharing property in consistent language
- [ ] This repo's own flake uses them, so the wording is dogfooded
