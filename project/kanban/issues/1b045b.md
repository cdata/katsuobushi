## What to fix

`sandbox prune` cannot reap a ref once its instance's state dir is gone, which
is what the documented lifecycle guarantees will happen.

`prune` enumerates candidates from the per-instance **state directories**. But
`sandbox stop --remove` deletes the state dir while leaving
`refs/remotes/sandbox-guest/<inst>` in the host repo — that ref is deliberately
retained as the revert artifact until the card is accepted. So the normal order
of operations is:

1. card reaches `ready`; orchestrator runs `sandbox stop --remove` on the pair
   (the skill says to do exactly this — the instances are spent)
2. product owner accepts the card some time later
3. `sandbox prune` now finds no state dirs, reports `nothing to prune`, and the
   refs it exists to collect are unreachable to it forever

Observed at the end of the PDD004 thread: nine accepted cards, **16** orphaned
`refs/remotes/sandbox-guest/*` refs, and `prune` reporting `nothing to prune`.
They had to be deleted by hand with `git update-ref -d`. The same applies to the
18 `refs/heads/sandbox/*` migration-debris refs.

The state dir is the wrong index. A ref is reapable when its card is terminal,
whether or not an instance directory still exists.

Enumerate from the **refs** in the namespaces the tool owns
(`refs/remotes/sandbox-guest/*`, and the legacy `refs/heads/sandbox/*`), map
`card-<id>-<suffix>` back to a card, and reap when that card is terminal. Keep
the existing conservative rules: only `card-<id>`-shaped names, and skip
anything whose card is not provably terminal.

Do **not** extend the reaper to namespaces the tool does not own. In particular
`refs/heads/review/*` is ordinary user branch space — an orchestrator improvised
those before `sandbox deliver` was reachable, and a reaper that deletes refs it
never created, matching on a name pattern alone, is a data-loss bug rather than
a cleanup.

## Acceptance criteria

- [ ] `prune` reaps a `sandbox-guest` ref for a terminal card whose state dir
      has already been removed
- [ ] It still reaps state dirs for terminal cards that do have one
- [ ] Legacy `refs/heads/sandbox/*` refs for terminal cards are reaped too
- [ ] A ref whose card is not terminal, is absent from the board, or is not
      `card-<id>`-shaped is left alone
- [ ] Refs outside the tool-owned namespaces are never touched
- [ ] A test covers the state-dir-absent case specifically, since that is the
      case the current implementation cannot reach
