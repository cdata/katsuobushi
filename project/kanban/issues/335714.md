## What to build

Card `9689a8` shipped a library heartbeat set and its peer review confirmed the
checks work when run by hand inside a VM. The review also recorded four smaller
defects around the wiring. None blocked that card. Together they are worth one
pass.

- **Silent absence.** When `KATSU_SHIPPED_HEARTBEATS` is unset the server skips
  the shipped directory with no log line and no error (`server.rs:1071-1073`). A
  deployed VM always has the variable, so the failure is invisible exactly where
  it is most confusing — a non-Nix development environment, where the protection
  the card exists to guarantee is simply absent and nothing says so.
- **A doc comment that is wrong.** `runner.rs:34` says `run_heartbeat_set`
  "Never returns normally". It spawns its tasks and returns; the *inner* tasks
  are the ones that never return.
- **Undefined-looking label collision.** A project heartbeat carrying the same
  label as a shipped one is not deduplicated. Both run and both appear in the
  work state. That follows from "a project directory adds to the shipped set, it
  never replaces it", so the behaviour is right — but it is neither documented
  nor tested, and a reader would reasonably expect the project file to win.
- **A latent Nix build failure.** The `*.yaml` glob at `default.nix:357` would
  fail the build if the shipped heartbeat directory ever became empty.

## Acceptance criteria

- [ ] A server started with `KATSU_SHIPPED_HEARTBEATS` unset says so on stderr,
      once, naming what is missing and what it means.
- [ ] `run_heartbeat_set`'s doc comment describes what the function actually
      does.
- [ ] The label-collision rule is stated where a heartbeat author will read it,
      and a test pins it.
- [ ] An empty shipped heartbeat directory does not fail the Nix build.
- [ ] A test covers an empty `hb_dirs`.
- [ ] `clippy -D warnings` is clean.
