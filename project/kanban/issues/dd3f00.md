## What to build

`TurnBeat` grew an `arm()` / `silence()` pair in card `0e8753`, and its five unit
tests drive that pair. Production does not use it. `run_turn_heartbeat` assigns
`beat.armed` from the `AtomicBool` and calls `tick()` directly
(`runner.rs:59-60`), so `arm()` and `silence()` are effectively test-only.

Two consequences the peer reviewer recorded, neither of them blocking on its own:

- `arm()`'s documentation says it records the arm time as `beat_started` "so
  duration is measured from the turn's first activity". That is not true of the
  running system. `beat_started` is set at the first tick after the flag flips —
  up to one interval, so up to 10 seconds, late. Immaterial against a 60-minute
  timeout, but the doc describes a path production never takes.
- The unit tests therefore pin an API that no running code calls. They are not
  wrong, but they are weaker evidence than their names suggest.

Close the gap rather than papering over it. Either route the runner through
`arm()` / `silence()` so the tested path is the real one, or delete the pair and
test the assignment the runner actually performs. Prefer the first if it can be
done without making the runner hold a lock across a tick.

Two tests were also missing and should land with whichever route is taken.

## Acceptance criteria

- [ ] The code path the unit tests exercise is the same one `run_turn_heartbeat`
      takes in production.
- [ ] No public method on `TurnBeat` is reachable only from tests.
- [ ] `arm()`'s documentation matches observable behaviour, or the method is gone.
- [ ] A test covers `TurnEnded` arriving before any `TurnAccepted`.
- [ ] A test verifies `execute_outcome` performs the `store(true)` and
      `store(false)` on the shared flag, not merely that the `Outcome` flags were
      set.
- [ ] `clippy -D warnings` is clean.

## Review notes

### Round 1 — `review-dd3f00-b8541511` — VERDICT: accept

Gates observed by the reviewer: 553 tests pass, lint clean.

- **Gap closed.** `runner.rs:106-110` matches on `(prev_armed, cur_armed)` and
  dispatches `arm()` / `silence()` / `tick()`. `TurnBeat::armed` is private
  (`heartbeat.rs:217`) and the old direct assignment is gone, so no caller can
  bypass the pair. Every public method is now reachable from production.
- **The first arm cannot be missed.** `prev_armed` starts `false`, so a flag
  already `true` at the runner's first tick still produces a `(false, true)`
  edge and calls `arm()`.
- **A sub-tick turn does vanish — but this is pre-existing, not new.** If
  `TurnAccepted` and `TurnEnded` both land inside one 10s interval, the runner
  sees `(false, false)` and no beat is ever emitted. The reviewer checked the
  old code and it produced *identical* results, so the edge model changed
  nothing here. Judged right for a 10s-sampled flag. Nothing documents the
  sub-tick disappearance; noted, not blocking.
- **Observable timing is unchanged and the new doc is now true.**
  `beat_started` was always set at the first tick that saw the flag, both before
  and after. The *old* doc was simply wrong; the new one
  (`heartbeat.rs:227-229`) correctly says "first interval that observed the arm
  — up to one interval (10 s) after `TurnAccepted` fires".
- **Both new tests prove their names.**
  `it_stores_true_then_false_on_the_shared_flag_via_execute_outcome`
  (`server.rs:1967`) drives `execute_outcome` and then reads
  `ctl.turn_armed.load(...)` **directly** — it does not re-assert on `Outcome`
  fields under a better name, which was the specific way this card could have
  been faked. The original gap is genuinely closed.
- **No existing test was weakened or deleted.** `turn_beat_tests` only ever
  called the public methods, so making the field private broke nothing.
