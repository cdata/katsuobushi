## What to build

`TurnBeat` grew an `arm()` / `silence()` pair in card `0e8753`, and its five unit
tests drive that pair. Production does not use it. `run_turn_heartbeat` assigns
`beat.armed` from the `AtomicBool` and calls `tick()` directly
(`runner.rs:59-60`), so `arm()` and `silence()` are effectively test-only.

Two consequences the peer reviewer recorded, neither of them blocking on its own:

- `arm()`'s documentation says it records the arm time as `beat_started` "so
  duration is measured from the turn's first activity". That is not true of the
  running system. `beat_started` is set at the first tick after the flag flips —
  up to one interval, so up to 10 seconds, late. Immaterial against a 60-minute
  timeout, but the doc describes a path production never takes.
- The unit tests therefore pin an API that no running code calls. They are not
  wrong, but they are weaker evidence than their names suggest.

Close the gap rather than papering over it. Either route the runner through
`arm()` / `silence()` so the tested path is the real one, or delete the pair and
test the assignment the runner actually performs. Prefer the first if it can be
done without making the runner hold a lock across a tick.

Two tests were also missing and should land with whichever route is taken.

## Acceptance criteria

- [ ] The code path the unit tests exercise is the same one `run_turn_heartbeat`
      takes in production.
- [ ] No public method on `TurnBeat` is reachable only from tests.
- [ ] `arm()`'s documentation matches observable behaviour, or the method is gone.
- [ ] A test covers `TurnEnded` arriving before any `TurnAccepted`.
- [ ] A test verifies `execute_outcome` performs the `store(true)` and
      `store(false)` on the shared flag, not merely that the `Outcome` flags were
      set.
- [ ] `clippy -D warnings` is clean.
