## What to build

Retire the `design:` frontmatter field. Its meaning already lives in labels.
Remove it from the note schema and the card face, and migrate any note that
still carries it with `lint --fix`.

- **Drop `design` from the note.** Remove the field from `NoteMeta` and stop
  parsing/rendering it. Legacy `design:` lines on disk survive untouched (the
  parser is a line editor, not a serde round-trip) until the migration reads
  them.
- **Drop the `design` column from the card face.** Remove the `design` entry
  from the `metadata-keys` settings block so a freshly `init`ed board renders no
  `design` column.
- **`lint --fix` migrates legacy notes.** For each note that still carries a
  `design: X` key: append `X` to `labels`, then remove the `design:` key. Also
  rewrite the on-disk board settings block to drop the `design` column. A second
  `lint` run reports no change (idempotent).

### Seam (verified against the tree)

- `NoteMeta.design` field (`note.rs:248`), its parse (`note.rs:276`), and its
  conditional emit in `render_new_note` (`note.rs:317-319`) — remove all three.
  `render_new_note`'s `design` parameter goes away (update its one caller in
  `new.rs`; card 02 already stops passing a real design scalar).
- `CardView.design` (`query.rs:35`, populated near `:189`) — remove.
- Settings block: delete exactly the `{"metadataKey":"design",...}` element at
  `layout.rs:163`; keep the rest of the `serde_json::json!` block and the `%%
  kanban:settings ... %%` fence byte-for-byte. This only affects newly `init`ed
  boards — existing boards keep the column in `Board::trailer` until the
  migration rewrites it.
- No frontmatter **key-removal** primitive exists today — only `set_scalar`
  upsert (`note.rs:209`). Add a `remove`/`rename` helper on `Note` reusing
  `find_key` (`note.rs:125`) and `continuation_end` (`note.rs:227`) so a removed
  key also drops any Prettier-wrapped continuation lines, and unknown keys stay
  byte-stable.
- The migration reads a legacy `design` via `Note::get_scalar("design")`
  (still available even after `NoteMeta` drops the field) and writes labels
  through the same list-writer path so the note round-trips byte-stable under
  Prettier/Obsidian.
- `lint --fix` lives in `lint.rs:75` (`run(..., fix)`).

## Acceptance criteria

- [ ] `NoteMeta` no longer has a `design` field; new notes render no `design:`.
- [ ] A newly `init`ed board's settings block has no `design` column, rest
      byte-identical.
- [ ] `project lint --fix` folds a legacy `design: X` into `labels` and removes
      the `design:` key, preserving unknown keys byte-for-byte.
- [ ] `lint --fix` also drops the `design` column from an existing board's
      settings block.
- [ ] A second `lint --fix` run reports no change.
- [ ] Unit tests, BDD-named: `it_folds_a_legacy_design_field_into_labels`,
      `it_drops_the_design_key_from_the_note`,
      `it_drops_the_design_column_from_the_board_settings`,
      `it_is_idempotent_on_a_second_run`.
