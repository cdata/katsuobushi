## What to build

F3b of `design/warm-artifacts.md`. `sandbox dispatch` composes its directive
from `.dispatch-instructions.md` plus the card; it should also inline the
project's menu, generated at compose time so it cannot drift from the commands
that actually exist. Expand one level, since only top-level nodes become rows
(`lib/menu/default.nix:143`) and the leaves are what the agent will type.

**This is not a text change (§13.2).** `menuText` is a shell snippet that echoes
colorized `name;description` pairs (`lib/menu/default.nix:292-322`), and the
sub-level tree exists only in Nix — `katsuctl` never sees it. So this needs a
plain/JSON menu rendering in `lib.menu` carried through the guest spec, which is
`specVersion` surface: the Rust-side bump and the Nix-render bump must land in
the *same* change or every launch fails.

Pairs with F3d — the directive should also state that dependencies are pre-built
and the target dir seeded, and that a `cargo check` which starts compiling
third-party crates means seeding failed and should be reported rather than
waited out.

## Acceptance criteria

- [ ] `lib.menu` exposes a plain (uncolored) rendering, one level expanded
- [ ] The rendering reaches `katsuctl` via the spec; `specVersion` bumped on both
      sides in one change
- [ ] `dispatch` inlines it; `directive.md` shows it, so `--redeliver` keeps it
- [ ] A project with no menu still dispatches
