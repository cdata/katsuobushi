## What to fix

Raised by the independent reviewer of card `283f02` as a non-blocking finding
and accepted alongside it, so it is filed rather than bounced.

`283f02` added an abort to the landing guard in the `sandbox` skill: when
unexpected residue remains staged under `project/kanban/` after the restoring
checkout, the recipe prints an error to stderr and runs `exit 1`.

The reviewer established the behaviour empirically:

- Pasted into an **interactive terminal**, `exit 1` ends the operator's shell
  session.
- Run in a **subshell** — which is how an agent executing a bash tool call runs
  it — it exits only the subshell, and the parent survives.

The error message reaches stderr before the exit in both cases, so the cause is
visible either way. This is a standard emergency-abort pattern and not a
correctness defect, which is why it did not block. But the landing procedure is
written for a human orchestrator to run at a terminal, and nothing in the skill
warns that pasting this block can close their shell.

## Why it matters

The landing procedure is one of the most-followed recipes in the skill, and it
is presented as something to run by hand. An operator who hits the abort path —
already an unhappy path, mid-landing, with a partially staged merge — loses
their terminal at exactly the moment they most need to inspect state.

## What to fix

Options, roughly in order of preference:

- Restructure the guard so the failure path does not need `exit` — for example
  wrap the check in a function or subshell (`( … )`), or use a conditional that
  skips the remaining steps rather than terminating.
- Or keep `exit 1` and say plainly in the surrounding prose that the block
  should be run as a script or in a subshell, not pasted into an interactive
  shell.

## Acceptance criteria

- [ ] The landing guard's abort path does not close an interactive operator's shell, or the skill warns that it will
- [ ] The abort still surfaces the error and still prevents the landing from continuing
- [ ] The plain-git and jj-colocated blocks stay consistent with each other

## Review notes

Reviewed by `review-442c4e-bdda6467` against branch tip `d568fcd`.
**VERDICT: accept**, all three criteria satisfied, verified against scratch git
repos rather than by reading.

**The structural question — where `git commit` sits.** Read from the literal
text: both recipes wrap the *entire* block in `( … )`, with `git commit` on the
second-to-last line **inside** the closing paren. `exit 1` fires earlier in the
same subshell, so the commit never runs. Confirmed empirically — the scratch
repo's commit count was unchanged after the abort path executed. AC 2 holds.

- **AC 1** — satisfied. `bash --norc -c` with a subshell containing `exit 1`
  leaves the outer shell alive; the old recipe's bare `exit 1` killed it.
- **AC 2** — satisfied. Messages go to stderr via `printf … >&2` before the
  exit, so the cause is visible, and the landing cannot proceed.
- **AC 3** — satisfied. Both blocks share an identical guard structure and both
  place `git commit` inside the parens.

**The one semantic change beyond wrapping:** `jj git import` moved from *after*
the subshell to *inside* it. That is a correction, not an accident — it must be
gated by the same guard as the commit it imports. The rest of the +37/-33 is
re-indentation (two spaces for everything now inside the parens).

No shell state crosses the subshell boundary: `_board`, `_checkout_residue` and
`_f` are all set and consumed inside it; no `cd`, no exports. Agent behaviour is
unchanged — a single bash call still exits 1 on abort, 0 on success.

Edge case recorded, deliberately **not** filed: an operator running with
`set -e` in their interactive session will still lose that session, because the
subshell's non-zero status propagates. The reviewer judged this a pre-existing
limitation of any failure-signalling recipe rather than a defect of this change,
and the fix is strictly better in the ordinary (no `set -e`) case. Filing it
would mean chasing shell semantics that no recipe here can fully escape.

Markdown gate clean. Scratch repos deleted; nothing left running.
