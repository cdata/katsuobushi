## What to build

`sandbox deliver` force-pushes into the target mirror as
`refs/heads/delivered/<basename>`, which makes re-delivery idempotent. Nothing
tells a guest that the namespace is orchestrator-owned.

If a guest commits on top of a previously-delivered `delivered/<basename>`, the
next re-delivery silently force-overwrites that work. `fetch` has an orphan
guard for the analogous host-side risk; `deliver` has none, by design.

Document the contract rather than add a guard: state in the `sandbox` skill,
next to the `sandbox deliver` verb, that `delivered/*` is orchestrator-managed,
that a guest must treat it as read-only, and that a re-delivery overwrites it.

Found by the peer reviewer of card 69d1df; not blocking that card.

## Acceptance criteria

- [ ] The `sandbox` skill states that `delivered/*` is orchestrator-owned and
      read-only to a guest
- [ ] It states that re-delivery force-overwrites, and what a guest loses if it
      committed there


## Added after filing

The peer reviewer of card `9d09df` found a second defect in the same file:
`deliver.rs`'s module doc names **base refresh** as a use case the verb serves.
It cannot. `deliver` writes `refs/heads/delivered/<basename>`; a base refresh
needs `refs/heads/base`. Correct the module doc along with the namespace
contract.

Also found while orchestrating: `katsuctl sandbox deliver` works, but the
project's `sandbox` wrapper does not list or accept `deliver`, so the verb is
unreachable through the command operators actually use. Card `69d1df`'s
acceptance criterion said the command should live "beside the other sandbox
verbs". Wire the verb into the wrapper's subcommand list.
