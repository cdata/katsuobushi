## What to build

A dispatch can silently seed a guest from a stale base. The guest then builds
against a tree that is missing work the orchestrator has already landed, and
nothing reports it.

`resolve_seed` in `rust/katsuobushi-controller/src/sandbox/start.rs` (around
lines 457-458) takes the seed from `git stash create`, "falling back to `HEAD`
when the tree is clean and `stash create` prints nothing". The fallback keys on
*empty output*. But `git stash create` also prints nothing when it **fails**:

```
$ git stash create
error: Entry 'project/kanban/issues/2c0b55.md' not uptodate. Cannot merge.
Cannot save the current worktree state
$ echo $?          # non-zero, stdout empty
```

An empty stdout is read as "clean tree", so the seed falls back to `HEAD` and
every working-copy change is dropped from the guest's mirror without a word.

Observed in this session. Card `9d09df` was dispatched after `69d1df` landed,
and its branch has no `deliver.rs` and no `Deliver` wiring in `main.rs` — it was
seeded from `HEAD`, one commit behind. The guest's whole test run was against a
base the orchestrator had already moved past.

A stale git index is the trigger, and a **colocated jj repo reaches that state
routinely**: `jj` writes the working copy without keeping git's index in step, so
`git stash create` starts failing until something runs `git add`. That also means
git `HEAD` tracks jj's `@-`, so anything committed jj-natively is invisible to a
seed that has fallen back to `HEAD`.

Distinguish failure from a clean tree. A `stash create` that exits non-zero must
not be read as "nothing to stash" — fail the dispatch loudly, or refresh the
index and retry. Failing closed is right here: a silently stale guest wastes a
whole dispatch and can return work built on a base that no longer exists.

## Acceptance criteria

- [ ] A `git stash create` that exits non-zero fails the dispatch with a clear
      message naming the cause, instead of falling back to `HEAD`
- [ ] The clean-tree fallback still works when `stash create` genuinely has
      nothing to save (exit zero, empty stdout)
- [ ] A unit test through the host seam covers non-zero-exit-with-empty-stdout
      separately from zero-exit-with-empty-stdout
- [ ] The colocated-jj trigger is documented wherever the seeding behaviour is
      described
