## What to build

Make the repeatable label the canonical way to tag a new card, and demote the
`design:` field to a deprecated alias that appends a label.

- **Canonical: `project new --label`.** Repeatable and comma-splittable
  (`--label=a,b` or `--label=a --label=b`). The older `--labels` spelling keeps
  working as an alias, so existing scripts do not break.
- **Deprecated: `project new --design <ref>`.** It prints a deprecation warning
  and appends `<ref>` to the card's labels. It must no longer write a `design:`
  frontmatter field — the reference becomes a label like any other. Both
  spellings keep working the day a consumer updates.

This card is CLI + wiring only. Retiring the `design` frontmatter field from the
note schema and card face, and migrating legacy notes, is a separate card.
