## What to build

The `sandbox` command resolves from the shell that launched the orchestrator, not
from the current working tree. On a long session that shell's binary is a fixed
store path, so it keeps launching guests built from the flake **as it was when the
session started** — even after changes to `lib/sandbox` or the guest `packages`
have landed.

This is not hypothetical. Card `4e542e` adds `pkgs.jujutsu` to the guest packages.
Its peer reviewer ran `jj --version` inside its own guest and got
`command not found`, because that guest had been launched by the stale binary and
was built from the pre-change flake. The reviewer diagnosed it correctly — the
derivation was present in the store but not linked into the system profile — and
had to fall back to invoking `jj` by store path to review the card at all.

So a reviewer asked to verify a guest-affecting change can be handed a guest that
does not contain it, and nothing warns either party. The review still reached the
right verdict here only because the reviewer noticed and said so.

The same mechanism bit the fetch refspec earlier in the session: `sandbox fetch`
from the stale binary wrote the old `refs/heads/` namespace after the new
`refs/remotes/` behaviour had landed, silently re-creating debris the fix was
meant to eliminate.

Decide how to close the gap. Options worth weighing rather than assuming:

- Have `sandbox` report the flake revision or store path its guest image was built
  from, so a mismatch is visible in `sandbox status` and in launch output.
- Have the orchestration guidance say plainly that a card changing the guest image
  or the sandbox library must be reviewed by a guest launched from a rebuilt
  binary, and how to do that (`nix develop -c sandbox …`).
- Detect staleness directly — compare the running binary's build input against the
  working tree and warn on divergence.

## Acceptance criteria

- [ ] An orchestrator can tell, without guessing, whether a launched guest
      contains the working tree's current sandbox configuration.
- [ ] A reviewer dispatched to verify a guest-affecting change is not silently
      given a guest that predates it.
- [ ] The failure mode is written down where an orchestrator will meet it.
- [ ] `nix develop -c markdown lint` is clean.
