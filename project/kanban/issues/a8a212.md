## What to build

The contract stops teaching the agent how to do its work. Foreground and
background are the agent's choice.

The prescription leaves both places that carry it today:

- the agent contract in `lib/sandbox/default.nix` (lines 565 to 570), which
  tells the agent to run long commands in the foreground;
- the dispatch instructions in `project/kanban/.dispatch-instructions.md`
  (lines 16 to 18), which tell it to start the cold build in the background.

The two sides disagree with each other, and neither is right. A rewording toward
foreground blocking does not work: one Bash call caps at 600 seconds unless
`BASH_MAX_TIMEOUT_MS` raises it, nothing in `lib/sandbox/default.nix` sets it,
and a 15-minute build therefore has no foreground path. After this design
nothing needs one.

What the contract keeps:

- A terminal report is required to return work to the host. This is unchanged.
- Incremental reports are offered as an option, not an obligation.

## Acceptance criteria

- [ ] A search of both files finds no rule preferring foreground or background.
- [ ] A search of both files finds the terminal-report requirement, unchanged.
- [ ] Incremental reports read as an option in both files, not an obligation.
- [ ] Neither file tells the agent to `report working` before it yields.
