## What to build

Say **orchestrator-only** where the skills now say **host-only**.

The board is written by one role, not by one machine. That role runs on the host
today and does not have to. Naming the machine couples the rule to a deployment
detail, and a later design that moves the orchestrator into its own sandbox then
reads as a contradiction.

Known sites:

- `plugins/katsuobushi/skills/project-orchestration/SKILL.md` line 80 — the
  heading "The board is host-only (an invariant)".
- `plugins/katsuobushi/skills/sandbox/SKILL.md` line 307 — "`project/kanban/` …
  is host-only state, and the host is its single writer".
- `rust/katsuobushi-controller/src/sandbox/dispatch.rs` line 351 — the comment
  "The board is host-only (design/PDD001)".

Sweep for others rather than trusting this list.

This is a rename of the **role**, not of every mention of the host. Where the
prose genuinely means the machine — the host seam, the host repo, `HostImpl` —
leave it. The guest-facing rule is unchanged in substance: a guest never writes
the board.

## Acceptance criteria

- [ ] The skills say the board is orchestrator-only state and the orchestrator
      is its single writer
- [ ] No skill couples the board-writer role to the host machine
- [ ] The `dispatch.rs` comment matches the skills
- [ ] Mentions of the host that genuinely mean the machine are left alone


## Review notes

Peer review by an independent VM: **VERDICT needs-changes.** All four gates green
(markdown format/lint, rust lint/test). The changes that were made are accurate —
the reviewer confirmed no true statement was over-corrected, the `dispatch.rs`
comment is right, and every exclusion (CHANGELOG, MIGRATING.md, design docs,
`lib/sandbox/README.md`) is a legitimate reference to the host *machine*.

The problem is coverage, not correctness. The acceptance bar is PDD004's test
case — "no skill couples the role to the host machine" — not the literal string
`host-only`.

**Blocking 1: the role is still defined as the host agent** in
`project-orchestration/SKILL.md` at three sites — the four-roles table's Who
column ("the host agent (not sandboxed) — normally you"), the section heading
("The orchestrator (you, the host agent)"), and that section's opening sentence.
PDD004 says the role runs on the host *today* but could later move into its own
sandbox, and "for that reason this document says 'orchestrator' and never 'host'
for the role".

**Blocking 2: `project/kanban/.dispatch-instructions.md` was missed** — line 42
still reads "host-only state; the host is its single writer", the exact phrase
renamed everywhere else. This is the highest-impact site in the sweep: that file
is prepended to every dispatch directive, so every dispatched agent is currently
taught the superseded rule. Found by the reviewer; missed by both the author and
the orchestrator.

**Non-blocking:** `sandbox/SKILL.md` line 23 says "host orchestrator".
