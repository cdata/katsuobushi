## What to build

`sandbox status` cannot see the stall class above. When an instance idles after
a yield, the only signal is `turn-state.json`'s `lastActivityAt`, which an
operator has to know to go looking for. The `sandbox` skill says to inspect
`console.log` when something looks stuck, but that log stops at the login prompt
(all six were ~26KB of pure boot output, nothing about agent runtime).

Surface a liveness / idle field on `sandbox status` so the yield-and-die class
is visible without knowing the internals — e.g.:

```
card-34071f   phase: ended-unreported   idle 33m (no activity since last yield)
```

Drive it off `lastActivityAt` (and the phase marker). An idle-since-yield
duration in both the human and `--json` output would have caught the dominant
failure instantly.

## Acceptance criteria

- [ ] `sandbox status` reports an idle duration derived from `lastActivityAt`
      for each instance, in both human and `--json` output.
- [ ] An instance in `ended-unreported` with a stale `lastActivityAt` is
      visually distinguishable from a healthy working instance.
- [ ] The `sandbox` skill's "looks stuck" guidance points at this field, not
      just `console.log`.
