## What happened

`sandbox status`'s reads all go through the `Host` trait, and
`report_log::read`/`latest_terminal_at` are deliberately `#[cfg(test)]` to keep
it that way. The **write** side does not follow suit: `directive::write`
(`rust/katsuobushi-controller/src/sandbox/directive.rs`) and
`report_log::append` (`.../report_log.rs`) call `std::fs` directly, and
`report_log`'s own module docs flag seam discipline as a hazard before doing
exactly this.

It works — both are called from non-seamed entry points — but it means neither
write path can be exercised with a `FakeHost`, so their failure modes
(unwritable dir, partial write) are testable only by building real files in a
tempdir.

## Suggested fix

Route both through `Host::write` (adding an append affordance for the journal),
or state explicitly in each module why the seam does not apply to writes.

## Acceptance criteria

- [ ] Either the writes go through the seam, or the exemption is documented
      where a reader will find it.
