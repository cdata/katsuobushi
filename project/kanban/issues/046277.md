## What to fix

Raised by the independent reviewer of card `3fd9ec` as two non-blocking
findings, accepted alongside it and filed together here because they are one
unit of work: leftovers from removing the idle-transition nudge path.

`3fd9ec` removed the `is_work_idle` guard from `GraceExpired` and deleted the
`nudge_pending` field and the `WorkStateIdle` nudge-firing path. Two artifacts
of the old design survive:

- **Dead state.** `is_work_idle` in the guest server is still *set* but never
  *read*. Its doc comment still describes the behaviour it used to gate.
- **Stale prose.** A comment in `lib/sandbox/default.nix` still describes the
  old idle-transition behaviour, which no longer exists.

Neither affects runtime behaviour, which is why the reviewer did not block.

## Why it matters

Dead state that is still maintained is a trap for the next reader: it looks
load-bearing, so a future change may try to preserve its semantics, or wire new
logic onto a flag that no longer means anything. The stale comments actively
describe behaviour the code no longer has, which is worse than no comment.

## What to fix

- Remove `is_work_idle` if nothing reads it, along with the code that maintains
  it — or, if it is worth keeping for diagnostics, say so explicitly in its doc
  comment and make that its stated purpose.
- Update the doc comment either way.
- Correct the `lib/sandbox/default.nix` comment to describe the current
  nudge behaviour.
- While there, check for any other comment in the guest server or the sandbox
  library that still describes the pre-`3fd9ec` idle-transition design.

## Acceptance criteria

- [ ] `is_work_idle` is either removed or documented with its actual current purpose
- [ ] No comment in the guest server describes the removed idle-transition nudge behaviour
- [ ] The `lib/sandbox/default.nix` comment matches the current nudge behaviour
- [ ] The workspace gate stays green
