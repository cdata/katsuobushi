## What to build

F2 of `design/warm-artifacts.md`. `lib.sandbox` gains a `warm` list; `lib.rust`
exposes `warmSet` so the common case is one line that cannot drift from the
builders it names. `sandbox dispatch` and `sandbox start --agent` run
`nix build --no-link` over the warm set before boot, so the guest inherits the
paths over the read-only store share instead of rebuilding them.

This moves a compile otherwise paid *per VM at its configured vCPU count* to the
host *once at full core count*; every VM in a swarm after the first is free.

**Guard the claim (§13.3).** `dispatch` claims the card (`todo → in-progress`)
before it launches, so a warm-set build failure introduces a new failure point
after the claim. Either roll the claim back or make the warm step non-fatal —
otherwise this recreates the "a dispatch that fails after the claim leaves the
card in-progress" gotcha the orchestration skill already documents.

## Acceptance criteria

- [ ] `warm` accepted by `lib.sandbox`; `rust.warmSet` exposed and used in-repo
- [ ] `dispatch` / `start --agent` realize the set before boot, with progress
      visible (it is a long step, and must not read as a hang)
- [ ] A warm-set build failure does not strand a claimed card
- [ ] Skipping the warm step is possible for a fast/offline launch
