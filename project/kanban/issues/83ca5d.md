## What to build

State the board's single-writer rule as an invariant, not a habit: **the host is
the only writer of `project/kanban/`.** A sandbox guest never writes the board.
It gets its card as prose in its directive, returns code as a git branch, and
returns findings as `report` lines; the host reads those and makes every board
change. This closes the card-note conflict class — with one writer, two writers
cannot collide.

This card is documentation/guidance plus a confirmation. The design notes the
practice is already in place; the past breakage came from a directive that told
an agent to write its own findings into a card note.

### Seam (verified against the tree)

- `dispatch::compose_directive` (`dispatch.rs:98-133`) already gives the guest
  the card as prose only and instructs `report done` / `report blocked`; it never
  tells the guest to write `project/kanban/`. Confirm this stays true (a test or
  a comment asserting the directive never references the board path is welcome
  but optional).
- Document the invariant where a person authoring a directive would read it:
  - `plugins/katsuobushi/skills/sandbox/SKILL.md`
  - `plugins/katsuobushi/skills/project-orchestration/SKILL.md`
  - `project/kanban/.dispatch-instructions.md`
  State plainly: never tell an agent to write a finding into a card note;
  findings return through the `report` channel, and the host writes them down.

Scope note: auto-commit of board mutations and a `doctor` health command are
explicit **non-goals** of this design — do not build them here.

## Acceptance criteria

- [ ] The host-only board invariant is stated in the sandbox and
      project-orchestration skills and in `.dispatch-instructions.md`.
- [ ] The guidance explicitly forbids directing a guest to write a finding into
      a card note and points findings at the `report` channel.
- [ ] Confirmed (in the card's review notes) that `dispatch` composes the card as
      prose only and never instructs a board write.
