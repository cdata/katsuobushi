## What to fix

Raised by the independent reviewer of card `12bead` as a non-blocking finding
and accepted alongside it, so it is filed rather than bounced.

`12bead` added a landing guard to the `sandbox` skill that restores the board
after a squash merge:

```sh
git checkout HEAD -- project/kanban/ >/dev/null 2>&1 || true
```

The `|| true` is **load-bearing** and must not simply be deleted: `git checkout`
on a directory exits non-zero when any path under it is absent from HEAD — the
guest-added-file case — and suppressing that is what allows the following
cleanup loop to run.

The cost is that the same suppression swallows a checkout failure arising from
any *other* cause. The orchestrator would see a landing that appears to have
guarded the board when it did not. That sits awkwardly with `12bead`'s own
AC 3: "If a guest branch does touch the board, the landing says so rather than
merging it quietly."

## What to fix

Distinguish the expected non-zero exit (paths absent from HEAD) from an
unexpected failure, so the first stays quiet and the second is reported. For
example, check the specific condition rather than blanket-suppressing, or verify
after the fact that `git diff --cached -- project/kanban/` is empty and say so
loudly when it is not.

## Acceptance criteria

- [ ] An unexpected `git checkout` failure during the landing guard is surfaced, not swallowed
- [ ] The guest-added-file case still works without noise
- [ ] The landing procedure still satisfies `12bead`'s AC 3
