## What to build

Decide and implement the board-mutation durability guard that closes
Mechanism A (uncommitted board edits stranded when `jj new <landed-rev>`
advances the working copy during a landing).

The tension: the obvious fix is **auto-commit each `project` mutation** so there
is never uncommitted board state to strand. But the host workflow signs commits
with a YubiKey that is not always present, and a failed signature needs an agent
to interpret the error and adapt — so a blind auto-commit-per-mutation is not
obviously safe. Options to weigh:

- **Auto-commit each mutation** (`status set` / `new` / `prioritize` seal into
  their own commit). Kills Mechanism A structurally. Must handle the
  signing-key-absent failure gracefully (surface the error, don't half-apply).
- **Refuse-to-mutate while BOARD.md is dirty** (weaker; nags mid-flow but never
  clobbers).
- **`project doctor`** as a backstop (flag a dirty board / a lane change with no
  matching commit) rather than an active guard.

Deferred pending the board-overhaul PDD. This card is in the **icebox** (note
exists, no board card) until that design is settled.

## Acceptance criteria

- [ ] The chosen guard is specified in the board-overhaul PDD.
- [ ] The guard interacts correctly with jj commit signing when the YubiKey is
      absent (no silent half-applied mutation).
