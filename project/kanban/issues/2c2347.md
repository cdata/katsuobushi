## What to build

Card `c72eb6` made reviewer instance naming contractual: the `--name` slug must be
the card id, and `sandbox prune` skips anything it cannot map. Two operational
gaps follow from that, and both were found by using the workflow rather than
reading it.

**There is no documented way to get a fresh second reviewer.** The orchestration
skill says to *pause* a reviewer between rounds so the re-review starts warm,
which is right. It never says what to do when the existing reviewer should not be
reused — for example when it has already disproved an earlier attempt and you want
an uncontaminated opinion. In this session that produced an instance named
`review-850ce4b`, invented to sit beside the paused `review-850ce4`, which the new
contract makes unreapable. The peer reviewer ruled that a second reviewer should
**replace** the first: `sandbox stop --remove review-<card-id>`, then start again
with the same name. Say that in the skill, next to the pause guidance, so the
question is answered where it is asked.

**Off-contract instances are never reaped.** `prune` skips any name it cannot map
to a card, which is the correct fail-closed behaviour, but it means an instance
named off-contract accumulates silently forever. Say plainly that such instances
need `sandbox stop --remove` by hand, and how to spot them.

## Acceptance criteria

- [ ] The orchestration skill states that a fresh second reviewer replaces the
      first, with the remove-then-restart commands, beside the existing pause
      guidance.
- [ ] The skill says off-contract instance names are never pruned and must be
      removed by hand.
- [ ] A reader can tell from the skill alone why the name must be exactly the card
      id.
- [ ] `nix develop -c markdown lint` is clean.
