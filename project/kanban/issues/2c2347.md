## What to build

Card `c72eb6` made reviewer instance naming contractual: the `--name` slug must be
the card id, and `sandbox prune` skips anything it cannot map. Two operational
gaps follow from that, and both were found by using the workflow rather than
reading it.

**There is no documented way to get a fresh second reviewer.** The orchestration
skill says to *pause* a reviewer between rounds so the re-review starts warm,
which is right. It never says what to do when the existing reviewer should not be
reused — for example when it has already disproved an earlier attempt and you want
an uncontaminated opinion. In this session that produced an instance named
`review-850ce4b`, invented to sit beside the paused `review-850ce4`, which the new
contract makes unreapable. The peer reviewer ruled that a second reviewer should
**replace** the first: `sandbox stop --remove review-<card-id>`, then start again
with the same name. Say that in the skill, next to the pause guidance, so the
question is answered where it is asked.

**Off-contract instances are never reaped.** `prune` skips any name it cannot map
to a card, which is the correct fail-closed behaviour, but it means an instance
named off-contract accumulates silently forever. Say plainly that such instances
need `sandbox stop --remove` by hand, and how to spot them.

## Acceptance criteria

- [ ] The skill says off-contract instance names are never pruned and must be

- [ ] A reader can tell from the skill alone why the name must be exactly the card

## Review notes

### Round 1 — `review-2c2347-941072f2` — VERDICT: needs-changes

`markdown lint` clean; no Rust changed and the reviewer said so.

**Passed:**

- **Placement** — the off-contract warning sits right after the `--name` rule
  (`:108-121`), the replace guidance right after the pause commands
  (`:307-323`), with a cross-reference binding them.
- **When, not just how** — the prose gives a concrete test: *is this reviewer's
  opinion still trustworthy? If yes, pause. If contaminated, replace.* The
  judgement is made rather than described.
- **The naming rule states its reason** (`:109-110`) — `prune` maps by that exact
  convention — not just the rule.

**BLOCKING — the skill now contradicts itself in plain text.** The Gotchas
section (`:427-431`) says unconditionally *"Don't `--remove` a VM whose card is
still in review… Pause instead"*. The new replace guidance is precisely the
exception that Gotcha prohibits, and the Gotcha was not updated. A reader who
reaches it after reading the new section sees a flat prohibition with no
carve-out; the forward pointer only helps if they follow it.

**Borderline — the warm-cache cost is not acknowledged at the decision point.**
The replace block says to run `sandbox stop --remove` without noting that this
discards the warm build cache. The *next* paragraph explains what pausing
preserves and calls the rebuild "the dominant latency in a multi-turn review
loop" — but it is written as a reason to pause, not as an accepted cost of
deliberate replacement. A reader who acts on the commands and stops there never
meets the tradeoff. The skill already has the right idiom elsewhere: *"take the
cold build knowingly"* (`:354`).

**Secondary inconsistency:** the "remove only when its work is truly spent" list
(`:337-344`) enumerates four cases, and intentional replacement of a functional
reviewer fits none of them.
