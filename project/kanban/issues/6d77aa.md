## What to build

`jj metaedit --update-author` is the re-authoring mechanism card `9344ec`
documents in the sandbox skill. In this repository it does not work, and it fails
in the worst way: **it reports success.**

Observed repeatedly on jj 0.41.0:

```
$ jj metaedit --update-author -r 'nrurlyrr | tknuwtlw | ryvozwov'
Modified 3 commits:
  ryvozwov 5ac7f6b6 docs(orchestration): document fresh-reviewer protocol …
  tknuwtlw 62beedaa docs(orchestration): fix three contradictions …
  nrurlyrr ba807ff0 feat(sandbox): refuse dispatch when agent-authored commits …

$ jj log -r 'nrurlyrr | tknuwtlw | ryvozwov' -T 'commit_id.short() ++ author.email()'
9bf7545dae58  agent@katsuobushi.local
b8187322dcae  agent@katsuobushi.local
9f89191ca985  agent@katsuobushi.local
```

The commits are unchanged, the change ids still resolve to the **old** commit
ids, and `jj op log` records **no operation** for the metaedit — the most recent
operations are the preceding `jj new` / `jj duplicate`. Re-running produces a
different set of "new" commit ids each time, with the same non-effect.

Two things it is **not**. It is not an immutability refusal: an immutable target
produces a loud `Commit … is immutable` error, which was also observed and is a
different outcome. And it is not a bad invocation: `-r` is documented as an alias
for the positional `REVSETS` argument, and the command names exactly the intended
commits back.

It is also not uniformly broken — the same command re-authored at least one
landed commit earlier in the same session, verified by reading `author.email()`
afterwards. The condition that distinguishes the two cases is unknown and is the
thing to find.

Work out why, then fix the documented procedure. Possible directions, none
verified: an interaction with the colocated git repo's automatic export/import
cycle reverting the rewrite; a jj 0.41-specific defect; or something about
commits produced by `jj duplicate` specifically, since every failing case here
was a duplicate.

Until it is understood, `9344ec`'s procedure tells an orchestrator to run a
command that may silently do nothing.

## Acceptance criteria

- [ ] The condition under which `jj metaedit --update-author` silently no-ops is
      identified and written down.
- [ ] The sandbox skill documents a re-authoring mechanism that is verified to
      work, or documents the failure mode and a check.
- [ ] The procedure requires verifying the author after re-authoring rather than
      trusting the command's own success report.
- [ ] If the cause is upstream, it is reported upstream and the report is linked
      here.
